# Проверяемое демо Career Quest

Сценарий использует исходный `backend/Dataset`, дату **2026-10-01** и два реальных
синтетических профиля: **E0015** и **E0137**. Имена курсов сохранены на языке каталога.
Все значения ниже рассчитаны до изменения целей и подтверждения активностей.

## Воспроизведение расчётов одной командой

Из корня проекта в PowerShell:

```powershell
.\.venv\Scripts\python.exe scripts\demo_scenario.py --output var/demo_report.json
```

Скрипт проверяет первый эффект, повторное подтверждение и сохранение грейда,
показывает три альтернативы для каждого профиля и сравнение с выбором по самому
низкому навыку. Он читает исходный датасет напрямую, не вызывает модель, не меняет
SQLite и не загружает `.env`. Полный локальный отчёт — `var/demo_report.json`.
Можно передать `--data-dir`, `--as-of-date`, `--simple-id`, `--complex-id`.

Для презентации в браузере запускайте обычную команду:

```powershell
.\.venv\Scripts\python.exe scripts\run.py
```

Откройте `http://127.0.0.1:8000`. Коды для входа сотрудниками и HR находятся
в локальном `var/demo_accounts.json`, который создаёт сервер. Не публикуйте этот
файл. Для повторного показа с чистым демо-состоянием можно перед запуском задать
`DATABASE_PATH` на новый файл в `var` и `AS_OF_DATE=2026-10-01`; исходные JSON/CSV
переписывать или удалять не нужно. Если менялся каталог, загрузите стартовый набор
через экран импорта HR.

## Профиль 1: понятный первый шаг и обновление состояния

Войдите как сотрудник **E0015**. Роль **Frontend Engineer**, текущий грейд **Middle**,
цель **Frontend Engineer / Senior**. Начальное покрытие требований — **53,70%**,
остаток критических разрывов — **4**.

1. Покажите профиль, требования цели и историю. Эти данные открываются независимо
   от модели. Перейдите к рассчитанным сценариям.
2. Сравните первый шаг трёх маршрутов:

| Первый шаг | Покрытие после первого шага | Остаток критических разрывов | Покрытие после всего маршрута |
|---|---:|---:|---:|
| EV_015 · Web Performance Fundamentals | 57,41% | 3 | 59,26% |
| EV_005 · System Design Fundamentals | 55,56% | 4 | 59,26% |
| EV_017 · React Patterns & State Management | 55,56% | 4 | 59,26% |

3. У **EV_015** формат `self_paced`, длительность 6 часов. Изменение
   `SK_WEB_PERFORMANCE`: **2 → 3**, требование цели **4**, потолок курса **3**.
   Это достижимый шаг, который ещё не закрывает всё требование.
4. Подтвердите выполнение EV_015 в демо. Покрытие станет **57,41%**, критические
   разрывы — **3**, навык — **3**. Текущий грейд останется **Middle**.
5. После пересчёта доступны два полезных маршрута:
   `route_EV_005` и `route_EV_017_EV_005`. EV_015 не предлагается повторно.
   Повторная отправка того же подтверждения не добавляет навык второй раз;
   это также проверяют API-тесты и локальный скрипт.

Цифра на карточке относится к первому шагу. Итог пары шагов выводится отдельно.
Даты завершения в сценариях получены из допущения о двух часах обучения в день.

## Профиль 2: почему самого низкого навыка недостаточно

Выйдите и войдите как **E0137**. Роль **Backend Engineer**, грейд **Middle**,
следующая цель **Backend Engineer / Senior**. Начальное покрытие — **63,79%**,
критические разрывы — **3**.

| Выбор | Покрытие после первого шага | Критические разрывы после первого шага |
|---|---:|---:|
| Однофакторный: EV_009 · Cloud Certification Prep, навык SK_CLOUD | 67,24% | 3 |
| Рассчитанный: EV_006 · Designing High-Load Systems | 72,41% | 1 |
| Альтернатива: EV_007 · Architecture Review Circle | 67,24% | 2 |
| Альтернатива: EV_010 · Kubernetes in Practice | 65,52% | 3 |

У EV_006 три реальных эффекта: `SK_SYSTEM_DESIGN` **2 → 3** при требовании **4**,
`SK_API_DESIGN` **3 → 4** при требовании **4**, `SK_OBSERVABILITY` **2 → 3** при
требовании **3**. Маршрут EV_006 → EV_007 достигает **75,86%** после двух шагов.

В истории очного формата за последний год есть **2 неявки**, завершений нет.
Программа учитывает это при сравнении формата и длительности, но не придумывает
причин и не выставляет сотруднику рейтинг. Здесь влияние на критические требования
остаётся сильнее сигнала формата. Сотрудник видит альтернативы и сам выбирает.
Первая доступная сессия EV_006 — **2026-10-07**: на дату снимка это сценарий будущего
обучения, а не уже выполненное событие.

## HR, права и модель

Войдите с ролью HR. На исходном снимке **200 сотрудников**, **40 активностей**,
**33 сотрудника без следующего доступного шага**. Покажите агрегаты компетенций,
статистику участия и конкретные причины отсутствия шага. Состояние после выполнения
EV_015 учитывается при следующем расчёте HR.

Сессия сотрудника не даёт открыть историю другого сотрудника или HR-API. HR имеет
доступ к этим данным. Это проверяется сервером, а не только скрытием кнопок.

В консоли `/admin/ai` HR может выполнить реальный запрос на фиксированном учебном
примере, который не содержит данных сотрудников. Только успешный проверенный ответ
получает `mode: llm`. `fallback` сопровождается причиной и не доказывает работу LLM.
Числа во всех карточках всегда рассчитаны backend; текст модели заменяется коротким
шаблоном из выбранных проверенных факторов. Само ранжирование кандидатов выполняет
модель, если вызов прошёл проверку. Порядок в таблицах выше относится к локальному
расчёту и может отличаться от разрешённой перестановки модели.

Для фактов профилей внешний контур требует явного `AI_ALLOW_EXTERNAL_DERIVED=true`
после разрешения организаторов. Без него внешняя интеграция сообщает
`external_not_allowed`; локальный loopback endpoint разрешён. В модель не передаются
ФИО, ID сотрудника/руководителя и строки исходной истории.

## Измеренные локальные расчёты

Запуск `scripts/demo_scenario.py` на демонстрационном компьютере, Python 3.14.7,
исходные 200 профилей, 2026-10-01:

| Расчёт | Число запусков | Медиана | Максимум |
|---|---:|---:|---:|
| Профиль E0015 | 5 | 0,046 мс | 0,101 мс |
| Рекомендации E0015 | 5 | 1,762 мс | 2,003 мс |
| Профиль E0137 | 5 | 0,060 мс | 0,129 мс |
| Рекомендации E0137 | 5 | 3,452 мс | 3,957 мс |
| HR по всем сотрудникам | 1 | 71,803 мс | 71,803 мс |

Это время локальных функций: оно не включает браузер, HTTP, SQLite и LLM. API отдаёт
отдельное время обработки в `Server-Timing` и `X-Response-Time-Ms`; браузер показывает
время загрузки. Для проверки требований 2/10 секунд используйте также эти измерения.
Вызов модели ограничен общим таймаутом 6 секунд и не повторяется автоматически.
